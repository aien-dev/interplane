Tests in `test_live_injection.py` and `test_analyze.py`.
- Closed-trace state is bounded and closing an unknown trace is a no-op (cross-language fix). Both SDKs recorded the id of an unknown trace on `close_trace` (10,000 unknown closes kept 10,000 ids, and each of those traces was then refused `session_closed`, against CORE.md), and both kept every closed id for the pipeline's life. Now a close of a trace holding no state records nothing; closed ids live in a window of the last `max_closed_traces` (4096) and older ones are retired into a fixed-size filter (`retired_filter_bits`, default 8388608 bits = 1 MiB, sha256 positions) that never forgets, so no closed or retired trace is admitted again; the filter can falsely refuse a never-used trace (fail closed; rate documented in CORE.md, about 5e-6 after 100,000 retirements). New `Limits` fields `max_closed_traces`, `retired_filter_bits` and `Pipeline.closed_trace_state()` in both SDKs; CORE.md "Closing a trace" rewritten. Same tests in `test_session_limits.py` and `session_limits.rs`, including 100,000 open/close cycles within the bound with every replay refused and shared vectors: filter refusals at 32 and 37 bits (37 is not a power of two, so a masking implementation fails) and exact filter positions at 1009 bits computed outside both SDKs. CORE.md states the bit layout and that closed-trace state is in memory only: a new pipeline forgets every closed id, so a host that restarts one must keep old trace ids out itself.
