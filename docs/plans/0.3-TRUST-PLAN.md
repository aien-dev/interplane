# INTERPLANE 0.3 "Trust": plan

Status: **plan, 2026-10-04**. Docs only. Nothing below is implemented by the PR that adds this
file. The gates are pre-registered separately in `bench/PROTOCOL-0.3.md` and are not restated
here. `STATUS.md` remains the only place that says what is implemented.

Governing rule (README.md:5): **models express intent, runtimes retain authority.** 0.3 makes the
line between content, model intent and runtime authority checkable: every model-visible input
says what it is and how far it is trusted, every injection attempt in a fixed corpus is shown not
to cause an effect, and approval and denial behave the same in both SDKs and both adapters.

Scope of the claim, fixed now: trust labels preserve meaning; they do not prove that a model
ignores injected text. 0.3 claims runtime-layer properties only. Model behaviour under injection is
measured and reported, never used as evidence that the boundary holds.

Inputs to this plan: ROADMAP.md (0.3 row), docs/REPORT-0.1.md, docs/REPORT-0.2.md, spec/,
both SDKs, both adapters, docs/audits/aien-authority-reaudit-2026-10-04.md, docs/external/ (Jan
#8975, NightDriver 565 and 666, ecosystem triage), and section 19 (IP-C) of the AIEN programming
plan of 2026-10-04 (operator document, not in this repository).

## 1. What exists today (main 678c06c)

Line numbers are at 678c06c unless another commit is named.

### Vocabulary and wire

- Two provenance axes exist on the wire: `ContentKind` (12 values) and `TrustLevel` (5 values)
  (`spec/schemas/common.schema.json:225-253`). Unknown trust strings are read as
  `external_untrusted`, unknown kinds as `unknown` (same file, `:252`; `spec/VERSIONING.md:9`).
- `result.provenance` carries `runtime`, `capability`, `duration_ms`, `result_digest`, `trusted`,
  `trust`, `content_kind` (`spec/schemas/result.schema.json:55-118`); the canonical shape and the
  null rules are pinned in `spec/CORE.md:86-101`.
- `Party` (envelope `source` and `destination`) also has optional `trust` and `content_kind`
  (`common.schema.json:26-69`; `envelope.schema.json:42-47`).
- Intent provenance records how a call was parsed: dialect, parser version, model, source turn,
  call id, digest of the native text, raw name, coercion (`spec/schemas/intent.schema.json:13-25`).
  It records nothing about what the model had seen when it produced the call.
- Trace relationship exists only at envelope level: `trace_id`, `message_id`, `parent_id`
  (`envelope.schema.json:20-38`; `CORE.md:24-29`).

### Behaviour

- The pipeline defaults an executed result with no kind to `tool_result` and with no trust to
  `unknown`; `trusted` is derived from `trust` (Rust `crates/interplane-crossveil/src/pipeline.rs:654-697`;
  Python `python/interplane/crossveil.py:186-194`; spec `CORE.md:89-101`, `CROSSVEIL.md:46-49`).
- Results are rendered to the model as data; markup inside a result is never parsed into a new
  intent. Conformance cases 22 (`web_fetch` with Qwen3.5 tool-call markup) and 23 (`recall_memory`)
  check it (`CORE.md:246-247`; mock payloads `CORE.md:160-161`).
- Retry after denial with a fabricated `extensions.approval_id` is denied again (case 18,
  `CORE.md:241`). A decision citing another request is denied (`pipeline.rs:406-420`). A stale
  mapping table is rejected before decide (case 21). Adapter exceptions fail closed
  (`CROSSVEIL.md:23-24`).
- The lifecycle allows REQUIRES_APPROVAL -> AUTHORIZED only through a new runtime decision
  carrying an `approval_id` (`CORE.md:50-60`; Rust `crates/interplane-core/src/lifecycle.rs:96-128`;
  Python `python/interplane/core.py:905-927`).

### Adapters

- Odysseus (pinned 2992bf6): decisions pass through Odysseus's own untrusted-context gate, which
  is monotonic per trace (`adapters/odysseus/interplane_adapter_odysseus/authority.py:140-145`,
  `:189-206`). Result trust comes from Odysseus's `result_integrity`
  (`authority.py:276`, `:292-294`). A gate refusal returns `requires_approval` with an opaque
  `odysseus-pending-<request_id>` handle that nothing consumes (`authority.py:198-206`;
  `docs/REPORT-0.1.md:86`). Odysseus itself has sealed, digest-bound approvals
  (`CURRENT_STATE.md:33`, citing Odysseus `src/tool_approvals.py:104-142`).
- AIEN (pinned sovereign-core 6554aac): effects go through the real `EffectLane` with
  `EffectClassAuthority`; single-use grants are issued through AIEN's `ApprovalDesk` and presented
  out of band per request id (`adapters/aien/src/lib.rs:302-325`, `:326-432`). Six approval
  tests: pending without grant, executes once, spent grant refused, replay returns the existing
  receipt, mismatch, expiry (`adapters/aien/tests/approval.rs:41-149`). Known limits: grants live
  in memory, a grant is spent at mint even if the provider then rejects the call, the host
  supplies the clock, the generic `Pipeline` has no grant field (`docs/REPORT-0.2.md:90-93`).
- AIEN's `aien-cli` `SafetyEngine` cannot be linked (private module); the adapter substitutes
  workspace confinement plus the AEGIS `pre_dispatch_check` gate and names the gate actually used
  in `authority.policy_engine` (`adapters/aien/README.md:95-105`).
- 0.2 bench already measured one model-behaviour number: on qwen3.5:9b, an injection attempt
  appeared in 1 of 5 injection runs in each condition
  (`bench/runs/qual-20261004T2207Z/summary.md:68`, `:88`).

## 3. Wire-format decision (made now)

All 0.3 additions are **optional fields** on the wire (a MINOR change, `VERSIONING.md:7`) and
**required by the 0.3 conformance gates**. No new `payload.kind` is added, because an unknown kind
is rejected by older receivers (`VERSIONING.md:18`). No new `TrustLevel` value is added (that is
MAJOR, `VERSIONING.md:9`). The 25 existing fixtures must keep their expected outcomes unchanged
(`VERSIONING.md:19-20`); new checks live in new fixtures or in new optional `expected` blocks.

Defined in P1 and P2 (names fixed now so the protocol can refer to them):

- **InputRecord** (new schema `spec/schemas/input.schema.json`): `input_id`, `content_kind`,
  `trust` (type `TrustLevel`; Drake's "trust_level"), `source` (a `Party`: who handed the bytes
  to the context), `origin` (a locator string for where the bytes came from: file path, URL,
  memory record id, provider id, `runtime:<id>`; may be a digest-only form for sensitive
  locators), `content_digest`, `trace_id`, `parent_id` (the `message_id` or `request_id` that
  produced it, null for host-registered inputs), `derived_from` (list of `input_id`s it was
  computed from, for summaries and nested content).
- **Exposure** (new optional `provenance.exposure` on `tool_request`, mirrored into
  `CallContext`): `{inputs: [input_id...], floor: TrustLevel}`, where `floor` is the least trusted
  level among inputs visible to the model when it produced the turn. Order: `trusted_runtime` >
  `user_supplied` > `workspace_untrusted` > `external_untrusted`; `unknown` counts as
  `external_untrusted`. The pipeline computes it from its own ledger. An `exposure` value arriving
  inside a model-produced or admitted envelope is discarded and recomputed, never read.
- **Model-generated content** (`content_kind = model_generated`) is recorded with trust
  `external_untrusted`. Models are untrusted by design (README.md "Security in one paragraph").
- **Unknown never becomes trusted by serialization.** Absent, null, unparseable or unrecognized
  trust round-trips as `unknown` or `external_untrusted`, and `trusted` is never `true` for it, in
  both SDKs and after JCS round-trip.

## 4. Lanes and cuts

Each cut is one PR. "Lockstep" means the Rust and Python changes land in the same PR and the
cross-language verdict comparison in CI (`.github/workflows/ci.yml:68-80`) stays byte-identical.
Owner types: **spec** (normative text and schemas), **SDK** (Rust + Python lockstep), **adapter**
(one host adapter, its pinned host checkout), **host** (a change in a host repository),
**taskmaster** (runs, report, status). Red before green: every cut that fixes behaviour first
lands a failing fixture or test in the same PR history.

### Lane A: approval and denial correctness

**A1. Approval continuation contract, and the Rust fix.** (spec + SDK; depends on P1)
- Spec first, in `CORE.md` and `CROSSVEIL.md`, before any code extends the API:
  - **Host-controlled.** Continuation is a host call with a runtime-produced decision. No field
    in `tool_request`, `arguments`, `extensions`, envelope or model text is read as a grant, and
    no model-writable field is added that could be mistaken for one.
  - **Correlation.** `trace_id` + `request_id` + the `approval_id` the runtime minted for that
    request + the digest of the original `capability_request` (binds capability and arguments).
    The approval applies to the exact effect that will run, not to a broader class that sounds
    like it (NightDriver 565 lesson, `docs/external/nightdriver/565/REPORT.md:79`).
  - **Expiry.** `approval.expires_at` checked against the host clock; expired means DENIED.
  - **Cancellation.** A host cancel turns REQUIRES_APPROVAL into DENIED; it is terminal.
  - **Replay.** A second continuation of the same request is refused. Protocol replay protection
    (`replayed_message`, `duplicate_request_id`) stays on; continuation is a transition on the
    existing ledger entry, never a re-admission, so resuming never disables duplicate detection.
    Host effect idempotency (AIEN's receipt ledger) is separate and is not reused for this.
  - **Restart.** Pipeline state is in memory; after a restart a pending request cannot be
    continued (fail closed). The host must start a new request.
- Code: Rust `Lifecycle` stores the minted id and checks it (`lifecycle.rs:62-65`, `:115-121`),
  matching Python (`core.py:924-926`). Red first: fixture with a foreign `approval_id` fails on
  Rust today.

**A2. Continuation entry point in both SDKs.** (SDK; depends on A1)
- `Pipeline` gains the host-only continuation call and cancel call; fixtures gain an
  `"approve"`/`"cancel"` step that only the fixture's host side can issue.
- Evidence: approval cases A01 to A14 of the protocol in both runners, byte-identical.

**A3. AIEN grants through the continuation API.** (adapter; depends on A2)

**A4. Odysseus approvals.** (adapter; depends on A2)

## 5. 0.3 acceptance (maps to the protocol gates)

1. Model content cannot forge approval (gate A, categories C07, C08, C10).
2. Mismatch, expiry, reuse and stale scope all refuse (gate A).
3. A legitimate approval resumes through the supported integration (gate A, A01 on both SDKs and
   AIEN; Odysseus resumes or fails closed).
4. Both SDKs have identical trust semantics (gate X: byte-identical verdicts on every fixture).
5. No effect executes from an untrusted-origin instruction (gate E, 0 tolerated).
6. Every model-visible input in conformance carries the required provenance (gate P).
7. The suite can fail: every negative-control variant fails it (gate N).

## 6. Explicitly OUT of 0.3

- **0.4 Execution:** Vectorveil transport, RelayLine streaming and execution, cancellation of
  running work, continuation across processes, durable execution receipts. Named follow-up
  **IP-D**: streaming assembly by call index, frame bounds, incomplete-call rejection, request
  ledger eviction and session bounds, unresolved result on unknown completion.
- **0.2.x expansion follow-up**, named **IP-B**: a new pre-registered protocol with a fresh
  held-out set (model discovery, stronger prompting, runtime-triggered expansion, reasoning off,
  compared separately). Exposure never grants, consumes or retries.
- **IP-A** (freeze and reproduce 0.2 evidence, classify the 0.2 execution errors, clean-checkout
  gates, dependency pinning) and **IP-E** (packaging, offline mock example, independent adapter
  implementer, repeated multi-model runs): named follow-ups, not 0.3 gates.
- Model-side defences used as controls: prompt framing, classifiers, fine-tuning. Lenshift
  framing of untrusted content in the rendered message (G5) is deferred to a later non-gating cut;
  if added it is an aid to the model, never part of a gate.
- Signatures (`envelope.signature` stays reserved), persistent grant storage inside AIEN, egress
  and exfiltration classification beyond each runtime's own effect class, delegated authority
  across sub-agents.
- Upstream changes to Odysseus itself.
