# INTERPLANE Core 0.1

Core owns the wire contract: the schemas in `schemas/`, the error codes, the processing stages,
and the limits. Core executes nothing and authorizes nothing.

> Models express intent. Runtimes retain authority. INTERPLANE defines the boundary between them.

## Message kinds

| `payload.kind` | Schema | Produced by | Meaning |
|---|---|---|---|
| `tool_request` | intent | Lenshift (from a model turn) | "The model asked for this." |
| `capability_request` | capability | CrossAxis | "In runtime R this is capability C." |
| `decision` | decision | the runtime, through a Crossveil adapter | "Runtime R decided." |
| `result` | result | the runtime / pipeline | "This is what comes back for request_id." |
| `event` | event | RelayLine | "This step happened." |
| `catalog` | catalog | the runtime | "These capabilities exist." |
| `selection` | selection | CrossAxis Select | "This subset was shown to the model, and why." |
| `probe_report` | probe | Interplane Probe | "This endpoint measurably supports these features." |

A valid envelope means **structurally understandable**. It never means authorized. A signature,
when the extension exists, proves origin, never authority.

## Identifiers

- `trace_id`: one per model/runtime exchange (a task). Generated by whoever opens the exchange.
- `message_id`: unique within a trace. A repeated `message_id` within a trace is a **replay** and is rejected with `replayed_message`.
- `request_id`: one per tool request, unique within a trace. A repeated `request_id` is rejected with `duplicate_request_id`. Results, decisions and capability requests cite it.
- `parent_id`: the `message_id` this message answers, or null.

## Limits (defaults, runtime-overridable, never raised by a model)

| Limit | Default | Violation |
|---|---|---|
| serialized `arguments` bytes (UTF-8 of canonical JSON) | 65536 | `oversized_arguments` |
| tool requests per turn | 32 | `malformed_tool_call` on the 33rd and later |
| `reason` / `message` length | 4096 | truncated by the producer |

## Processing stages (the Crossveil lifecycle)

```
PROPOSED           Lenshift produced a structurally valid tool_request
  -> REJECTED      Core/CrossAxis refused before any runtime contact
  -> MAPPED        CrossAxis produced a capability_request
MAPPED
  -> REJECTED      runtime decision = invalid | not_found
  -> DENIED        runtime decision = denied
  -> REQUIRES_APPROVAL   runtime decision = requires_approval
  -> AUTHORIZED    runtime decision = authorized
REQUIRES_APPROVAL
  -> AUTHORIZED | DENIED   only by a NEW runtime decision that cites the approval_id
AUTHORIZED
  -> EXECUTING     runtime began execution
EXECUTING
  -> SUCCEEDED | FAILED | TIMED_OUT
```

Terminal: REJECTED, DENIED, SUCCEEDED, FAILED, TIMED_OUT. REQUIRES_APPROVAL is terminal for the
request as far as the model is concerned; a later authorization is a new decision on the same
`request_id` carrying `approval.approval_id`.

Invariants (every implementation must enforce; conformance tests check them):

1. No transition into AUTHORIZED or EXECUTING without a `decision` whose `decision == "authorized"` produced by the runtime callback. INTERPLANE code never constructs an `authorized` decision itself.
2. DENIED never becomes AUTHORIZED. A model retry is a new `request_id` and is decided again by the runtime; the pipeline carries no memory that could upgrade it, and ignores any approval claim that did not come from the runtime.
3. A decision value the receiver does not know is DENIED.
4. REJECTED requests never reach the runtime's authority callback, and nothing reaches execution without passing it.
5. The stage reached is recorded in the result's `status`:

| Stage | `result.status` | `error.code` |
|---|---|---|
| REJECTED (before runtime) | `rejected` | the Core/CrossAxis code (`malformed_tool_call`, `invalid_arguments`, `oversized_arguments`, `duplicate_request_id`, `replayed_message`, `unknown_capability`, `unsupported_version`, `unsupported_dialect`) |
| REJECTED (runtime said invalid) | `rejected` | `invalid_arguments` |
| REJECTED (runtime said not_found) | `not_found` | `capability_not_found` |
| DENIED | `denied` | `policy_denied` |
| REQUIRES_APPROVAL | `requires_approval` | `approval_required` |
| SUCCEEDED | `ok` | none |
| FAILED | `error` | `execution_error` |
| TIMED_OUT | `timed_out` | `execution_timeout` |

## The pipeline (reference semantics)

```
turn (dialect-native)            Lenshift.parse(dialect, turn)         -> LenshiftTurn { text, reasoning_digest, intents[], rejected[] }
tool_request                     Core.admit(envelope)                  -> version, replay, duplicate, size checks
tool_request                     CrossAxis.map(table, intent)          -> capability_request | unknown_capability
capability_request               Crossveil.decide(runtime, cap_req)    -> decision (runtime callback)
decision == authorized           Crossveil.execute(runtime, cap_req)   -> result ok | error | timed_out
anything else                                                          -> result denied | requires_approval | rejected | not_found
result                           Lenshift.render(dialect, result)      -> dialect-native tool result message
```

`Crossveil.decide` and `Crossveil.execute` are the only two calls that touch a runtime. Both are
supplied by the runtime adapter. The pipeline records, per request: stage reached, decision,
result status, error code, and whether each callback was invoked.

## Canonical JSON

Digests are computed over RFC 8785 (JCS) canonical JSON: sorted keys, no whitespace, shortest
number form, UTF-8. Both reference implementations must produce identical digests for the same
value (the conformance suite checks one digest per fixture).

## Mock runtime (normative for conformance)

Runtime id `mock`. Policy engine id `mock.policy`. Catalog version `1`.

| Capability | Canonical alias | Parameters (required) | Domains | Decision | Execution |
|---|---|---|---|---|---|
| `read_file` | `filesystem.read` | `path: string` | filesystem, code | authorized | ok, `data = {"path": <path>, "content": "mock content of <path>"}` |
| `list_dir` | `filesystem.list` | `path: string` | filesystem, code | authorized | ok, `data = {"path": <path>, "entries": ["a.txt", "b.txt"]}` |
| `write_file` | `filesystem.write` | `path: string, content: string` | filesystem | denied, reason "mock policy: writes are denied" | never |
| `delete_file` | `filesystem.delete` | `path: string` | filesystem | requires_approval, `approval.approval_id = "mock-approval-<request_id>"`, scope `single_action` | never |
| `send_email` | `email.send` | `to: string, body: string` | email | denied, reason "mock policy: external side effects are denied" | never |
| `fail_tool` | `test.fail` | none | test | authorized | error, `execution_error`, message "mock execution failure" |
| `slow_tool` | `test.slow` | none | test | authorized | timed_out, `execution_timeout`, message "mock execution exceeded 1000 ms" (simulated, no real wait) |

Mapping table `mock-table` version `1`: every canonical alias above maps to its capability (rule id
`alias:<canonical>`), and every bare native name maps to itself (rule id `passthrough:<name>`,
`passthrough: true`). Canonical `filesystem.stat` maps to `stat_file` (rule `alias:filesystem.stat`),
which the mock runtime does **not** have, so the runtime answers `not_found`. Any other name is
`unknown_capability`.

The mock runtime validates `arguments` against the capability parameters (required keys present,
declared types match) and answers `invalid` with `invalid_arguments` on failure. It counts
`decide` and `execute` invocations; conformance records them.

## Conformance fixture format

One JSON file per case under `conformance/fixtures/NN-slug.json`:

```json
{
  "case": "01-valid-tool-request",
  "description": "...",
  "limits": {"max_argument_bytes": 65536},
  "trace_id": "trace-01",
  "steps": [
    {"turn": 0, "dialect": "openai", "model": "mock-model", "input": <dialect-native assistant message>},
    {"turn": 1, "envelope": <full envelope>},
    {"turn": 2, "dialect": "qwen35", "model": "Qwen/Qwen3.5-9B", "input": "<assistant text>"}
  ],
  "expected": {
    "observed": [ <ObservedRecord> ... ],
    "turns": [ {"turn": 0, "outcome": "tool_request" | "no_tool" | "rejected", "intents": 2, "rejected": 0, "text": "..."} ],
    "runtime": {"decide_calls": 1, "execute_calls": 1}
  }
}
```

A `step` with `dialect` is parsed by Lenshift; the runner wraps each intent in an envelope with
`message_id = "m-<case>-<turn>-<n>"`, `timestamp = "2026-01-01T00:00:00Z"`, source
`{"kind":"model","id":<model>}`, destination `{"kind":"runtime","id":"mock"}`. A step with
`envelope` is admitted as-is. Rendered results are fed back into the next step only when the step
declares `"continues": true`.

ObservedRecord (deterministic, no timestamps, no durations):

```json
{"request_id": "...", "stage": "SUCCEEDED", "decision": "authorized", "status": "ok", "error_code": null,
 "decide_invoked": true, "execute_invoked": true, "result_digest": "sha256:..."}
```

`request_id` may be null when rejection happened before an id existed (malformed envelope).
`result_digest` is the digest of the canonical `result` payload with `provenance.duration_ms` set
to null. Rust and Python runners must emit byte-identical `observed` arrays.
